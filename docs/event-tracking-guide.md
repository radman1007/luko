# راهنمای ثبتِ رویدادهای بازی (Event Tracking)

این سند برای سه گروه است: **تیمِ طراحیِ بازی**، **تیمِ پیاده‌سازیِ بازی** و هر کسی که بخواهد بداند
داده‌ی بازی‌ها چطور به پنلِ والدین می‌رسد. ساده نوشته شده؛ اگر فقط یک بخش به کارِ شماست، همان را بخوانید.

---

## ۱) کلِ ماجرا در یک نگاه

```
تیمِ طراحی                      تیمِ بازی‌ساز                     سایت و سرور                  پنلِ والدین
──────────                      ─────────────                     ───────────                  ───────────
تگِ آموزشی تعریف می‌کند   ──▶   در کدِ بازی، روی هر پاسخ   ──▶   رویداد را می‌گیرد،     ──▶   زمانِ بازی، خطای هر
(داشبورد ← تگ‌های آموزشی)       همان تگ را می‌فرستد               ذخیره و جمع می‌زند            مفهوم، موفقیت در اولین تلاش
```

- **تگِ آموزشی (concept tag)** یعنی کوچک‌ترین مهارتی که یک سؤال می‌سنجد؛ مثلاً `addition_2digit`
  یعنی «جمعِ دو رقمی».
- **رویداد (event)** یعنی هر اتفاقِ مهم در بازی: بچه جواب داد، راهنما گرفت، مرحله تمام شد، …
- بازی رویداد را با یک خط کد می‌فرستد (`LUKO.answer(...)`). بقیه‌اش، یعنی ارسال، ذخیره و نمودار،
  کارِ سایت است.

## ۲) تیمِ طراحیِ بازی — قدم به قدم

### قدم ۱: مفهوم‌های هر بازی را مشخص کنید
برای هر بازی بنویسید هر سؤال **دقیقاً چه چیزی** را می‌سنجد. هر مفهوم یک تگ می‌شود.

| خوب ✓ (ریز و مشخص) | بد ✗ (خیلی کلی) |
|---|---|
| `addition_2digit` — جمعِ دو رقمی | `math` |
| `addition_carry` — جمع با انتقال (ده‌بر یک) | `addition` (وقتی چند مهارتِ جدا دارد) |
| `compare_numbers` — مقایسه‌ی دو عدد | `numbers` |

### قدم ۲: کدِ تگ را درست بنویسید
- فقط **حروفِ کوچکِ انگلیسی، رقم، `_` و `-`**؛ با حرف شروع شود؛ حداکثر ۶۴ نویسه.
- مثال‌های درست: `addition_2digit`، `fraction_compare`، `letter_b`
- مثال‌های غلط: `Addition 2 digit` (فاصله و حرفِ بزرگ)، `جمع` (فارسی)، `2digit` (با رقم شروع شده)
- **بعد از این‌که بازی‌ها استفاده‌اش کردند، کد را عوض نکنید.** آمارِ قبلی جدا می‌شود. اگر لازم شد،
  تگِ تازه بسازید و قبلی را «غیرفعال» کنید.

### قدم ۳: تگ را در داشبورد ثبت کنید
داشبوردِ مدیریت ← **تگ‌های آموزشی** ← «تگِ تازه»:

| فیلد | چه بنویسید |
|---|---|
| کد | همان کدِ قدمِ ۲ |
| عنوان برای والدین | چیزی که پدر و مادر می‌فهمند: «جمعِ دو رقمی» |
| درس | ریاضی، علوم، قرآن، نگارش، هنر یا فارسی |
| پایه | پایه‌ی تحصیلی (یا «همه‌ی پایه‌ها») |
| توضیح برای تیمِ بازی‌سازی | این مفهوم دقیقاً چیست، یک سؤالِ نمونه، خطاهای رایج |

> برای ثبتِ تگ، حسابِ شما در داشبورد باید تیکِ «تگ‌های آموزشی» داشته باشد (مدیرِ کل می‌زند).

### قدم ۴: برای هر گزینه‌ی غلط، «نوعِ خطا» را تعیین کنید
این مهم‌ترین کارِ آموزشیِ شماست: والد می‌فهمد بچه **چرا** اشتباه کرده.

| `error_type` | یعنی | مثال (سؤال: ۱۷ + ۱۸ = ?) |
|---|---|---|
| `conceptual` | مفهوم را نفهمیده | جواب ۲۵: انتقالِ ده‌بر یک را نمی‌داند |
| `procedural` | مفهوم را دارد، در انجامش اشتباه کرده | جواب ۳۶: انتقال را بلد است ولی یکی جمعش غلط شد |
| `careless` | بی‌دقتی یا عجله | جواب ۵۳ به‌جای ۳۵: رقم‌ها را جابه‌جا نوشت |
| `timeout` | وقت تمام شد | جوابی نداد |
| `other` | هیچ‌کدام | — |

اگر برای یک گزینه نمی‌دانید، خالی بگذارید؛ حدسِ غلط از خالی بدتر است.

### قدم ۵: به تیمِ بازی‌ساز تحویل بدهید
برای هر بازی یک جدول مثلِ این بدهید:

| شناسه‌ی سؤال | تگ | پاسخِ درست | گزینه‌های غلط → نوعِ خطا |
|---|---|---|---|
| `q1` | `addition_2digit` | ۳۵ | ۲۵ → `conceptual` · ۵۳ → `careless` |
| `q2` | `addition_carry` | ۴۲ | ۳۲ → `conceptual` · ۴۳ → `procedural` |

### قدم ۶: بعد از انتشارِ بازی، «تگ‌های ثبت‌نشده» را نگاه کنید
در همان صفحه‌ی داشبورد، اگر بازی‌ای کدی فرستاده باشد که ثبت نشده (معمولاً غلطِ املایی مثلِ
`adition_2digit`)، با تعدادش نشان داده می‌شود. یا ثبتش کنید، یا به تیمِ بازی‌ساز بگویید درستش کنند.
**تا تگ ثبت نشود، والدین آن مفهوم را نمی‌بینند.** داده‌اش ولی گم نمی‌شود و بعد از ثبت دیده می‌شود.

## ۳) تیمِ پیاده‌سازیِ بازی — قدم به قدم

همه‌ی بازی‌ها فایلِ SDK را دارند. اگر بازیِ تازه دارد، این خط را در `<head>` بگذارید:

```html
<script src="/games/assets/luko-sdk.js"></script>
```

### قدم ۱: بازی را معرفی کنید (اولِ اسکریپت)
```js
LUKO.init({ gameType: 'quiz', totalLevels: 3 });   // چند مرحله دارد
```

### قدم ۲: شروعِ هر مرحله
```js
LUKO.startLevel(1, { title: 'مرحله‌ی ۱', concept: 'addition_2digit' });  // concept = تگِ پیش‌فرضِ این مرحله
```

### قدم ۳: وقتی سؤال روی صفحه آمد
```js
LUKO.question('q1', { concept: 'addition_2digit' });
```
از همین لحظه زمانِ پاسخ گرفته می‌شود. **شناسه‌ی سؤال (`'q1'`)** را همان بدهید که تیمِ طراحی داده.

### قدم ۴: هر بار که بچه جواب داد — مهم‌ترین خط
```js
LUKO.answer({
  concept: 'addition_2digit',   // تگِ آموزشی
  questionId: 'q1',             // همان شناسه‌ی قدمِ ۳ → SDK شماره‌ی تلاش را خودش می‌شمارد
  correct: false,               // حتماً true یا false (نه "false" به‌شکلِ رشته)
  errorType: 'careless',        // فقط برای پاسخِ غلط، از جدولِ تیمِ طراحی
  given: '53',                  // اختیاری: جوابِ بچه
  expected: '35',               // اختیاری: جوابِ درست
});
```
- اگر بچه دوباره به **همان سؤال** جواب داد، باز هم `LUKO.answer` با **همان `questionId`** بزنید؛ SDK
  می‌فهمد این تلاشِ دوم است. بدونِ `questionId` (یا `attempt`)، آن پاسخ در «موفقیت در اولین تلاش» شمرده نمی‌شود.
- زمانِ پاسخ را SDK از `LUKO.question` می‌گیرد. اگر بازی خودش زمان را دارد: `timeMs: 4500`.

### قدم ۵: راهنما و خطای غیرِپاسخ
```js
LUKO.hint('addition_2digit');                                     // بچه راهنما خواست
LUKO.mistake({ concept: 'addition_2digit', errorType: 'timeout' }); // وقت تمام شد، تیله افتاد، …
```

### قدم ۶: پایانِ مرحله و بازی
```js
LUKO.levelComplete({ score: 30 });   // مرحله برده شد؛ با آخرین مرحله بازی خودش تمام می‌شود
LUKO.levelFailed({ reason: 'lives' }); // مرحله باخته شد ولی بازی ادامه دارد
```
سکه را سرور می‌دهد؛ بازی هیچ عددی برای جایزه نمی‌فرستد.

### قدم ۷: آزمون — قبل از تحویل حتماً
1. بازی را با `?debug=1` باز کنید (مثلاً `/games/C2KrF1S1G1.html?debug=1`) و کنسولِ مرورگر را ببینید.
2. هر رویداد با `[LUKO]` در کنسول می‌آید. **هشدارهای زرد را صفر کنید**، مثلاً:
   - «concept_tag خالی است»: تگ را نداده‌اید.
   - «correct باید true یا false باشد»: رشته یا عدد فرستاده‌اید.
   - «errorType یکی از این‌هاست …»: نوعِ خطای غلط.
   - «شماره‌ی تلاش معلوم نیست»: `questionId` نداده‌اید.
3. نمونه‌ی کاملِ کارکرده: `/games/_reference/base-game.html`. دکمه‌هایش را بزنید و لاگِ رویدادها را ببینید.

### چک‌لیستِ تحویل
- [ ] `LUKO.init` با `totalLevels` درست
- [ ] هر سؤال `LUKO.question` و هر پاسخ `LUKO.answer` با `concept` و `questionId`
- [ ] `correct` همیشه بولی؛ `errorType` فقط از جدول
- [ ] همه‌ی تگ‌ها در داشبورد ثبت شده‌اند
- [ ] در `?debug=1` هیچ هشداری نیست
- [ ] هیچ نام، شماره یا متنِ آزادی از بچه فرستاده نمی‌شود؛ فقط عدد و کدهای کوتاه

### اگر از SDK استفاده نمی‌کنید (فقط برای موردِ خاص)
همان JSONِ بخشِ ۴ را با `postMessage` بفرستید:
```js
window.parent.postMessage({ type: 'luko-game-event', event: /* JSONِ بخشِ ۴ */ }, window.location.origin);
```
`event_id` (UUID) و `session_id` را خودتان بسازید و `timestamp` را میلی‌ثانیه بدهید. SDK همه‌ی این‌ها را
خودکار انجام می‌دهد، پس ترجیحاً از SDK استفاده کنید.

## ۴) فایلِ JSONِ رویداد

هر رویدادی که بازی می‌فرستد این شکل را دارد. فایلِ نمونه: [`telemetry/game-event.example.json`](telemetry/game-event.example.json)
و تعریفِ دقیق و ماشینی (JSON Schema): [`telemetry/game-event.schema.json`](telemetry/game-event.schema.json).

```json
{
  "schema_version": 3,
  "event_id": "9f1c2e0a-4b7d-4c1e-8a52-3d6f0b9e7a14",
  "session_id": "s-6b0e2c51-0f3a-4d2b-9c7e-1a8f4e2d9b30",
  "event_type": "answer",
  "concept_tag": "addition_2digit",
  "timestamp": 1760265000123,
  "level": 2,
  "data": {
    "is_correct": false,
    "time_taken_ms": 4500,
    "attempt_number": 2,
    "error_type": "conceptual",
    "hint_used": false,
    "question_id": "q7",
    "given": "35",
    "expected": "53"
  }
}
```

### متغیرها

| متغیر | نوع | لازم؟ | توضیح |
|---|---|---|---|
| `schema_version` | عدد | بله | نسخه‌ی قرارداد؛ همیشه `3` |
| `event_id` | متن (UUID) | بله | شناسه‌ی یکتای همین رویداد. اگر به‌خاطرِ قطعیِ اینترنت دوبار فرستاده شود، سرور یک‌بار ثبت می‌کند |
| `session_id` | متن | بله | یک بار بازی‌کردن، از بازکردنِ بازی تا بیرون‌رفتن. همه‌ی رویدادهای همان بار یکی‌اند |
| `event_type` | متن | بله | چه اتفاقی افتاد (جدولِ پایین) |
| `concept_tag` | متن | برای `answer`، `hint` و `mistake` | کدِ تگِ آموزشی؛ برای بقیه خالی (`""`) |
| `timestamp` | عدد | بله | زمانِ اتفاق روی دستگاهِ بچه، **میلی‌ثانیه** از ۱۹۷۰ (`Date.now()`) |
| `level` | عدد یا null | نه | شماره‌ی مرحله‌ی بازی |
| `data.is_correct` | true/false | برای `answer` | جواب درست بود یا نه |
| `data.time_taken_ms` | عدد | برای `answer` | چند میلی‌ثانیه فکر کرد (از نمایشِ سؤال یا تلاشِ قبلی) |
| `data.attempt_number` | عدد | خیلی مهم | چندمین تلاش روی همین سؤال؛ ۱ یعنی اولین بار |
| `data.error_type` | یکی از جدولِ قدمِ ۴ | برای پاسخِ غلط | چرا غلط بود |
| `data.hint_used` | true/false | نه | قبل از این جواب راهنما دیده بود؟ |
| `data.question_id` | متن | نه | شناسه‌ی سؤال در خودِ بازی |
| `data.given` / `data.expected` | متن یا عدد | نه | جوابِ بچه / جوابِ درست |
| `data.duration_ms` | عدد | در `level_end` | مدتِ فعالِ مرحله (بی‌زمانِ مکث) |
| `data.status`، `data.level_id`، `data.score` | — | خودکار | SDK برای زمینه اضافه می‌کند |

**`user_id` و `game_id` عمداً در JSON نیستند.** کاربر را سرور از ورودِ بچه می‌شناسد و شناسه‌ی بازی را
صفحه‌ی بازیِ سایت می‌گذارد. این‌طوری هیچ بازی‌ای نمی‌تواند به‌جای بچه‌ی دیگر یا بازیِ دیگر رویداد بفرستد.

### `event_type`ها

| نوع | کِی | چه کسی می‌فرستد |
|---|---|---|
| `game_loaded` | فایلِ بازی باز شد | SDK، خودکار |
| `game_start` | اولین حرکتِ واقعیِ بچه | SDK، خودکار |
| `level_start` / `level_end` | شروع و پایانِ هر مرحله | `startLevel` / `levelComplete` / `levelFailed` |
| `answer` | **هر جواب** | `LUKO.answer` |
| `hint` | راهنما | `LUKO.hint` |
| `mistake` | خطایی که جواب نیست | `LUKO.mistake` |
| `idle` / `pause` / `resume` | بی‌حرکتیِ بیش از ۳۰ ثانیه / پنهان‌شدنِ صفحه | SDK، خودکار |
| `game_over` | باختِ قطعی | `LUKO.gameOver` |
| `results_finalized` | پایانِ جلسه | SDK، خودکار |

پایانِ بازی (`game_complete`) و ترکِ وسطِ بازی (`game_end`) را سایت از روی خلاصه‌ی جلسه ثبت می‌کند.

### فرق با نمونه‌ی اولیه و دلیلش

| نمونه‌ی اولیه | الان | چرا |
|---|---|---|
| `user_id`، `game_id` در JSON | سایت اضافه می‌کند | امنیت؛ بازی نتواند جای کسِ دیگری بفرستد |
| `USER_ACTION` / `ERROR` / `HINT` / `GAME_COMPLETE` | `answer` / `hint` / `mistake` / `game_complete` | جوابِ غلط یک `answer` با `is_correct: false` است؛ اگر جدا «ERROR» هم ثبت شود، هر خطا دوبار شمرده می‌شود |
| `time_taken_seconds: 4.5` | `time_taken_ms: 4500` | عددِ صحیح، بی‌خطای اعشار |
| `timestamp` به ثانیه | به میلی‌ثانیه | ترتیبِ دقیقِ رویدادهای پشتِ‌سرِ هم |
| — | `event_id` | اینترنتِ قطع‌ووصل باعثِ ثبتِ تکراری نشود |
| — | `question_id`، `hint_used` | «اولین تلاش» و «با راهنما» درست حساب شوند |

## ۵) پشتِ صحنه: سایت و سرور (برای اطلاع)

1. **بازی ← سایت:** SDK رویداد را با `postMessage` به صفحه‌ی بازیِ سایت می‌دهد. این کار چند میکروثانیه
   طول می‌کشد و بازی هیچ‌وقت منتظرِ شبکه نمی‌ماند، پس افتِ فریم ندارد.
2. **سایت ← سرور:** `features/games/telemetry.ts` رویدادها را جمع می‌کند و هر ۵ ثانیه یا هر ۲۵ رویداد یک‌جا
   به `POST /api/v1/games/events` می‌فرستد. اگر اینترنت قطع باشد، رویدادها روی گوشی می‌مانند و بعداً
   می‌روند. موقعِ بستنِ صفحه هم با `fetch keepalive` فرستاده می‌شوند.
3. **سرور:** هر دسته با **یک** دستورِ پایگاه‌داده ذخیره می‌شود. رویدادِ تکراری (همان `event_id`) نادیده
   گرفته می‌شود و رویدادِ خراب کنار می‌رود بی‌آن‌که بقیه‌ی دسته از دست برود. فقط حسابِ دانش‌آموز می‌تواند
   بفرستد. سقف‌ها:
   - حداکثر ۲۰۰ رویداد در هر درخواست؛
   - حداکثر ۱۶KB دادهٔ اضافه برای هر رویداد؛
   - حداکثر ۱۵۰۰ درخواست در ساعت.

   زمانِ رویداد اگر بیش از ۵ دقیقه جلوتر از ساعتِ سرور یا بیش از ۳۰ روز قدیمی باشد، با زمانِ رسیدن ثبت می‌شود.
4. **جدول:** `games_gameevent`. هر رویداد یک ردیف دارد با ستون‌های
   - `user`، `game_slug`، `event_type`، `event_id`، `session_id`،
   - `occurred_at` (زمانِ واقعی)، `concept_tag`، `level`،
   - `is_correct`، `time_taken_ms`، `attempt_number`، `error_type`، `hint_used`، `duration_ms`،

   و بقیه‌ی داده‌ی خام در `payload`. تگ‌ها در جدولِ `games_concepttag`اند.

## ۶) عددهای پنلِ والدین چطور حساب می‌شوند

کد: `backend/apps/parent/learning.py`.

| عدد | محاسبه |
|---|---|
| **زمانِ بازیِ این هفته** | مجموعِ زمانِ **فعال** (بی‌مکث) در هفت روزِ اخیر. هر جلسه فقط یک‌بار شمرده می‌شود (بیشینه‌ی خلاصه‌های همان `session_id`). |
| **خطاهای هر تگ** | تعدادِ `answer`های با `is_correct = false` برای هر `concept_tag` در هشت هفته، به‌همراهِ نوعِ خطاها. |
| **موفقیت در اولین تلاش** | از پاسخ‌هایی که `attempt_number = 1` دارند، درصدِ درست‌ها. پاسخِ بی‌شماره‌ی تلاش حساب نمی‌شود تا عدد گمراه‌کننده نشود. |

این‌ها در تبِ «داشبورد» پنلِ والدین، کارتِ **«یادگیریِ مفهوم‌ها»**، نشان داده می‌شوند. فقط تگ‌های **ثبت‌شده و فعال**
به والد نشان داده می‌شوند.

---

## ۷) سؤال‌های رایج

**بازیِ قدیمی که `topic` می‌فرستد چه می‌شود؟** کار می‌کند؛ `topic` همان `concept` است. ولی تگش را در
داشبورد ثبت کنید.

**بچه بی‌اینترنت بازی کرد؟** رویدادها روی گوشی می‌مانند و با برگشتنِ اینترنت با زمانِ واقعیِ خودشان ثبت می‌شوند.

**مهمان (بی‌حساب)؟** رویدادِ مهمان فرستاده نمی‌شود.

**چه چیزی هرگز نباید فرستاده شود؟** نام، شماره، متنی که بچه تایپ کرده، یا هر داده‌ی شخصی. فقط عدد و کدهای کوتاه.

**تگی را اشتباه ساختم؟** اگر هنوز استفاده نشده، حذفش کنید. اگر استفاده شده، غیرفعالش کنید و تگِ درست را بسازید.
